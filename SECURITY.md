# Security Policy

## Supported versions

Security fixes target the latest published release and the current default branch. Older releases may not receive patches.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting option for this repository when it is available. Include the affected component (Host logic, pricing/usage engine, injected card script, or the bundle patch), impact, reproduction steps, and a suggested mitigation if known.

Do not publish API keys, balance figures, usage data, private repository data, or exploit code in a public issue. If private vulnerability reporting is unavailable, open a minimal issue asking the maintainer to establish a private contact channel; do not include vulnerability details.

Note: the plugin keeps the DeepSeek Harness API key on the Host and only displays local-log spend estimates. Reports that involve exposing credentials or other users' usage data are out of scope for public disclosure.

This project does not promise a fixed response or remediation time. A maintainer should acknowledge a valid private report, assess impact, coordinate a fix, and disclose details only after affected users have a reasonable opportunity to update.
